Counting is the hard part

Every usage billing project starts as an engineering problem and turns into a definitions problem by week two.

The question nobody has answered

What is one unit? For an API company that sounds obvious until you ask whether a 429 counts, whether a retry counts, whether a request that returned 500 counts, and whether a batch of 100 is one or a hundred. Every one of those has a defensible answer. Pick them before you write code.

Write it where finance can read it

If the definition lives in SQL, only the person who wrote the SQL can defend an invoice. That person leaves. This is the entire argument for declarative meters.

Test with the customer's own numbers

Take your three loudest customers and reproduce last month exactly. If you cannot match their own dashboard to the unit, the problem is the definition, not the pipeline.
